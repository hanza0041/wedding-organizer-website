# Functional requirements review

ทบทวน 17 พฤศจิกายน 2569 สำหรับคู่บ่าวสาวสองคนที่ใช้งานร่วมกัน ผ่าน Node server บนเครื่องและ Cloudflare Tunnel

## สิ่งที่มีแล้วหลังรอบนี้

| ด้าน | พฤติกรรมที่ใช้งานได้ | ข้อจำกัด |
| --- | --- | --- |
| พื้นที่คู่บ่าวสาว | ชวนด้วยลิงก์ แยกข้อมูลแต่ละคู่ อัปเดตข้าม browser | ใช้ลิงก์เป็นสิทธิ์เข้าถึง เลือกบทบาทเอง |
| สนทนา | 8 หัวข้อ คำถามตั้งต้น ข้อสรุปร่วม | ยังไม่มีไฟล์แนบ อ่านแล้ว หรือค้นหาข้อความ |
| เตรียมงาน | เพิ่ม/แก้/ลบ ผู้รับผิดชอบ วันเวลา หมวด สถานะและบันทึก | ยังไม่มีงานย่อยและ dependency |
| ตาราง | ปฏิทิน ตารางงาน ส่งออก ICS เลื่อนงานตามวันแต่ง | ICS เป็นการส่งออกครั้งเดียว ไม่มีการ sync กลับ |
| งบและค่าใช้จ่าย | งบรวม หมวด ผู้ให้บริการ ยอดรวมที่วางไว้ หมายเหตุ วันครบกำหนดถัดไป | ยังไม่แยกใบเสนอราคากับยอดตามสัญญา หรือวงเงินรายหมวด |
| การจ่าย | จ่ายจริงหลายงวด แหล่งเงิน/ผู้จ่าย วันจ่าย หมายเหตุ จ่ายแล้ว/คงค้าง | ยังไม่มีตารางงวดอนาคตหลายรายการต่อค่าใช้จ่าย |
| เงินรับ | เงินสมทบที่รับแล้วจากทั้งคู่/ครอบครัว/อื่น ๆ | ไม่มีการเชื่อมบัญชีธนาคาร หรือระบบซองของขวัญรายแขก |
| ประวัติการเงิน | บันทึกคน เวลา และข้อมูลก่อน/หลังแก้; UI แสดง 100 ครั้งล่าสุด | บทบาทเป็นสิ่งที่ผู้ใช้เลือก ไม่ใช่การยืนยันตัวตน ประวัติไม่ใช่บัญชีที่ป้องกันเจ้าของเครื่องแก้ DB |
| ส่งออก | CSV สรุปค่าใช้จ่าย; JSON รวมข้อมูลทั้งพื้นที่และรายการเงิน | ยังไม่มี import JSON / Excel หลายชีต |
| จัดเก็บ | SQLite, Docker Compose + named volume, snapshot backup, ย้าย local เข้า volume ว่าง | Backup ต้องนำไปเก็บนอกเครื่องเพิ่มเอง; ยังไม่ตั้ง schedule อัตโนมัติ |

## การเงิน: กติกาที่ต้องชัดเจน

- สกุลเงินเป็น THB เก็บจำนวนเงินใหม่เป็นจำนวนเต็มหน่วยสตางค์ เพื่อลดความคลาดเคลื่อนทศนิยม
- งบรวมคือเพดานที่ตกลง ไม่ใช่เงินสดที่รับเข้า
- ค่าใช้จ่ายที่วางไว้รวมยอดที่จ่ายไปแล้ว จึงไม่เอาสองตัวนี้มาบวกซ้ำ
- คงค้าง = ค่าใช้จ่ายทั้งหมด − จ่ายจริง; พื้นที่ในงบ = งบรวม − ค่าใช้จ่ายทั้งหมด
- เงินคงเหลือจากรายการที่บันทึก = เงินสมทบรับจริง − ยอดจ่ายทั้งหมด อาจติดลบหากยังลงเงินรับไม่ครบ
- รายการจ่ายต้องไม่เกินยอดคงค้าง ทั้งเมื่อจ่ายพร้อมกันหรือกดส่งซ้ำ คำขอซ้ำไม่สร้างรายการใหม่
- ลดค่าใช้จ่ายให้ต่ำกว่ายอดที่จ่ายแล้วไม่ได้ และลบค่าใช้จ่ายที่มีการจ่ายค้างอยู่ไม่ได้
- ยกเลิกบันทึกใช้แก้การลงข้อมูลผิด ประวัติยังอยู่; เงินคืนจริง/ยกเลิกสัญญาควรเป็นฟังก์ชันเฉพาะในรุ่นต่อไป
- การแก้ค่าใช้จ่ายชนกันต้องแจ้งให้เปิดข้อมูลล่าสุด แทนการทับค่าของอีกคนโดยไม่แจ้ง
- จำนวนเงินในหน้าเว็บเป็นการบันทึกด้วยตนเอง ไม่มีการโอนหรือหักเงินอัตโนมัติ

| P1 | แผนจ่ายหลายงวดและการเตือน | กำหนดแต่ละงวดล่วงหน้า ส่งเตือนก่อนครบกำหนด ระบุช่องทางและความยินยอมก่อนส่งข้อความออกภายนอก |
| P1 | สลิป/ใบเสร็จ + คืนเงิน | แนบหลักฐานกับการจ่าย บันทึกเงินคืนแยกจากลบข้อมูล จัดการยกเลิกสัญญาโดยเก็บประวัติครบ |
| P1 | ข้อสรุปเป็นงานได้ | สร้างงานจากข้อความ/ข้อสรุปพร้อมลิงก์กลับไปหัวข้อ ลดการจดซ้ำ |
| P2 | ผังโต๊ะและที่นั่ง | ใช้รายชื่อแขกเดียวกับ RSVP ส่งออกผังให้สถานที่ได้ |
| P2 | รันคิววันงาน | ผู้รับผิดชอบ เบอร์ติดต่อ จุดนัดหมาย แผนฝนตก และหน้าอ่านอย่างเดียวสำหรับผู้ประสานงาน |
| P2 | เปรียบเทียบตัวเลือก | สถานที่/แพ็กเกจ/ช่างภาพพร้อมราคา ข้อดีข้อจำกัด และสิ่งที่ทั้งคู่เลือก |

ไม่แนะนำเพิ่ม AI วางแผนอัตโนมัติ การเชื่อมธนาคาร หรือระบบชำระเงินก่อนข้อมูลแขก รายจ่าย สัญญา และการสำรองข้อมูลพร้อม

## ฐานข้อมูลและ Docker

**ข้อเสนอสำหรับเวอร์ชันนี้:** ใช้ SQLite ต่อ และเลือกได้ว่าจะรัน Node ตรง ๆ หรือใช้ Compose ไม่ต้องมี database server อีก container เพราะ SQLite ฝังอยู่ในแอปอยู่แล้ว

| รูปแบบ | ที่เก็บ | เหมาะกับ |
| --- | --- | --- |
| Node บนเครื่อง | `data/wedding.sqlite` หรือตาม `DB_PATH` | เริ่มเร็ว ดูไฟล์และสำรองได้ตรง ๆ |
| Compose + SQLite (เตรียมให้แล้ว) | `/app/data/wedding.sqlite` ใน volume `everafter_wedding-data` | รันซ้ำได้เหมือนกัน ข้อมูลอยู่ต่อเมื่อสร้าง container ใหม่ |
| Compose + PostgreSQL (ยังไม่ได้เปลี่ยน) | PostgreSQL data volume พร้อม migration/backup | หลายคู่หรือหลาย server ที่ต้องเขียนพร้อมกันมากขึ้น ต้องปรับโค้ดฐานข้อมูลและย้ายข้อมูลจริง ไม่ใช่เพิ่ม service เฉย ๆ |

Compose ช่วยจัดการการรัน ส่วนการคงอยู่ของข้อมูลมาจาก volume และการกู้คืนมาจาก backup สามส่วนนี้ทำหน้าที่ต่างกัน ไม่ควรถือว่า volume เป็น backup

อ้างอิง: [SQLite appropriate uses](https://www.sqlite.org/whentouse.html), [SQLite isolation](https://www.sqlite.org/isolation.html), [Docker volumes](https://docs.docker.com/reference/compose-file/volumes/), [Node SQLite backup](https://nodejs.org/download/release/latest-v24.x/docs/api/sqlite.html)
